Anthropic 엔지니어들이 Claude Code를 효율적으로 쓰는 핵심 전략 = **'프롬프트' 중심 → '스킬(Skills)' 중심으로 사고 전환**. 스킬은 재사용·조립 가능한 절차적 지식 패키지.

---

## 📐 AI 활용 계층 구조

| 계층 | 명칭 | 설명 |
|---|---|---|
| Layer 1 | AI 모델 | Claude 같은 기본 AI |
| Layer 2 | AI 에이전트 + 프롬프트 | 대부분 사용자가 머무는 영역 |
| **Layer 3** | **스킬 (Skills)** | **엔지니어가 직접 구축하는 제어 영역** |

---

## 🎯 4가지 핵심 규칙

### 규칙 1: 프롬프트가 아닌 '스킬' 활용
- 매번 긴 프롬프트 작성 X
- `/draft_email` 같은 사전 정의 스킬 호출 + 데이터만 입력
- 작업의 정형화·재사용성 확보

### 규칙 2: 스킬 = 3 레이어 구성
| 레이어 | 내용 |
|---|---|
| **Description** | Claude가 언제 이 스킬 쓸지 판단하는 기준 — 구체적일수록 자동 호출 정확 |
| **Instructions** | 호출 후 단계별 실행 가이드(플레이북) |
| **Tools** | 스크립트·API·참조 파일 — **가장 큰 레버리지, 가장 많이 간과됨** |

> Eric (Anthropic): "사람들은 프롬프트는 공들이지만 도구는 문서화도 안 된 상태로 둔다. 엔지니어라면 그렇게 안 한다."

### 규칙 3: 조립 가능(Composable) 스킬
- 거대한 단일 스킬 X
- **작고 집중된 스킬들** 다수 → 플러그인처럼 조립
- 장점:
  - 고장 시 어느 스킬이 문제인지 즉시 식별
  - 한 스킬 업데이트 → 이를 쓰는 모든 워크플로우 자동 개선 (복리 효과)
  - 새 워크플로우 만들 때 기존 스킬 재사용

### 규칙 4: 매 세션마다 진화
- 30일 차가 1일 차보다 나아야 함
- 출력 불만족 시 자문: **"일회성 수정? 영구 규칙?"**
  - 영구면 → 즉시 SKILL.md 업데이트
- 강화법: "방금 대화 검토해서 동일 실수 반복 안 하도록 스킬 강화해줘"

## 💎 핵심 기술 패턴

### 🔥 토큰 → 코드 연산 대체
| 방식 | 비용 | 결과 |
|---|---|---|
| AI에게 매번 Python 짜라 시킴 | 비쌈 (토큰) | 가변적 |
| **검증된 스크립트를 스킬 폴더에 도구로 저장** | 거의 0 | 결정론적 |

### 호출 제어 플래그
| 플래그 | 효과 |
|---|---|
| `user-invocable: false` | 사용자 메뉴에서 숨김 (에이전트 전용) |
| `disable-model-invocation` | 모델 직접 실행 차단 — 위험 작업(코드 배포·메시지 전송)에 인간 승인 강제 |

---

## 🎯 즉시 적용 가능 액션

1. **반복 계산은 Python 스크립트로 저장** (마진 계산, 가격 분석 등) → 토큰 절감
2. **각 스킬에 examples/ 폴더 추가** → 잘된 결과 누적 = 30일 효과
3. **위험 작업에 disable-model-invocation 적용** → 실수 방지
4. **세션 끝에 "스킬 강화해줘" 명령** → 지속 개선

## ⚠️ 주의사항

- 스킬이 너무 많아지면 영역 충돌 가능 → 주기적 통합·정리 필요
- 매 세션마다 강화하면 그것도 토큰 소모 → **주간 정리** 권장
- 창의적 작업(AI 아트 등)은 정형화 어려움 — 스킬화 강제 X
